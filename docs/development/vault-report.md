# Vault and encrypted-file implementation report

Status: implemented; the pinned Kotlin 2.3.21/JDK21 Gradle run passed 25 vault/archive/ZIP/file tests against the bundled native crypto library. The two conditional filesystem fault-injection cases are still pending. Android SQLCipher/device release gates remain unrun. Evidence: core/build/test-results/test/ and build-logs/core-app-jdk21-sdk36.log.

## Implemented

- Bounded, versioned dual-password header: Argon2id p=1, 64–256 MiB, 1–20 iterations, separate salts and wraps, complete-header keyed BLAKE2b authentication. Both KDF attempts and both unwraps execute before selection. Malformed KDF parameters are rejected before allocation. Independent 32-byte DB, file-base, and identity seed keys per slot.
- Password policy (updated 2026-09-17, task T4.10) uses the in-repo `estimateStrength` score 3, 12–128 characters of printable ASCII or Unicode letters with no control characters and no edge whitespace, UTF-8 **NFKC**, and real/panic passwords that are neither equal nor a trivial variation of each other (substring, or Levenshtein distance ≤ 2). The `com.nulab-inc:zxcvbn` dependency was removed with its last caller. Public manager/archive password inputs are consumed and zero-filled on all exits.
- Real KDF calibration targets approximately 2.5 seconds **per derivation**; unlock runs two derivations. Calibration raises costs from a supplied minimum and never lowers them. It stops at bounded resource limits; a measured device timing is still required.
- Storage adapter initializes both encrypted slots, checks matching nonzero DB byte lengths after adapter allocation alignment, mounts only selected storage, and closes the handle before wiping session key arrays. Session contains private wrapping/header keys needed for authenticated export and authorized panic reset.
- Stream file AEAD uses fresh 32-byte per-file keys, 64 KiB chunks, authenticated file ID/epoch/total length/index/record length/terminal flag, and a mandatory empty terminal record. Rejects wrong file/epoch, reordered chunks, modifications, truncation and extra bytes. No internal plaintext disk writes.
- Archive export/import uses bounded classic ZIP, explicit full local/central directory validation, canonical paths, duplicate/symlink/nonregular rejection, and a keyed manifest over ciphertext file sizes and streaming SHA-256 hashes. Entire incoming archive and extracted files are staged as ciphertext. Publication is a single atomic directory rename to an absent destination after password, full manifest and selected-store validation.
- Session-authenticated export requires no retained plaintext password and consumes/closes the session. Real-only panic reset replaces the decoy identity/data and preserves real keys; it rejects the real password as the replacement.
- Post-commit encrypted-backup/ZIP cleanup is best-effort: failure preserves the successful import/reset outcome and leaves the encrypted recovery artifact. Pre-commit cleanup likewise preserves the original error. A retained reset backup blocks another reset until reviewed; recovery never automatically chooses between two existing generations.

## Verification scope

Host tests in `VaultTest`, `VaultArchiveTest`, and `EncryptedFilesTest` call the real `NativeCrypto` provider. Test storage deliberately uses libsodium AEAD as an in-process adapter fixture; **it is not SQLCipher**. SQLCipher instrumentation, reserve sizing, lifecycle/network shutdown, device export/import, dump inspection, and the 100-unlock timing comparison belong to the Android integration/release suite.

The vault/files suite currently contains 25 normal test methods plus two opt-in cleanup fault tests. The host JNI library is `native/target/debug/libnomessages.so`, which is where `cargo build` places it and where `:core:test` looks by default; the `/tmp/nomessages-system-target/debug` path recorded earlier was a `CARGO_TARGET_DIR` override on the previous host and no longer exists. On that host the build owner had also staged a symlink under the central process's previously configured native path. Calibration now also wipes its acquired random secret if subsequent random salt generation fails; a focused regression test covers this exceptional path.

Initial test invocation `./gradlew :core:test --tests dev.mx3.nomessages.core.vault.VaultTest` could not run because the wrapper was not yet generated. A later shared runner invocation entered SDK bootstrap and was interrupted to avoid racing the build agent's installation. These are infrastructure failures, not passing test evidence.

An isolated Kotlin 2.0.21/JDK17 smoke compilation using Gradle's bundled compiler reached FIR checking but was interrupted (exit 130) at the coordinator's request to relieve host swap pressure. It produced no usable test result. The authoritative pinned Kotlin 2.3.21 build subsequently compiled successfully and ran the tests recorded above.

Source review is recorded in `docs/development/vault-review.md`. Two post-commit cleanup outcome findings were addressed in source and re-reviewed. A Linux host test fixture `core/src/test/native/vault_cleanup_faults.c` compiles successfully with `cc -shared -fPIC -O2 ... -ldl`; a process with `LD_PRELOAD=<fixture>.so NOMESSAGES_TEST_DENY_CLEANUP=1` (staged under `/tmp` on the previous host; that path is historical and must be rebuilt locally) was verified to receive EACCES for matching temporary ZIP deletion. Native-backed reset/import fault-injection runs remain pending. The fixture is never linked into production artifacts.

## Limits and honest caveats

- Matching DB **byte lengths** is enforced in core. The storage adapter must reserve equal encrypted SQLCipher pages and cap growth. Allocated blocks, media volume, access times, allocator behavior and forensic history can still differ. This is no proof of plausible deniability or coercion resistance.
- Stream decryption may emit an authenticated prefix before a later failure. Caller must discard incomplete output on any exception, keep the viewer output in memory, and never pass a disk plaintext stream. Export output can likewise be partial on failure; the caller owns final publication of the destination stream/file.
- Arrays are zero-filled on close, including exceptional close. Managed-runtime copies, the immutable `String` that `java.text.Normalizer` necessarily produces for the NFKC form, strength-estimator scratch buffers, IME buffers, OS caches and native call marshalling prevent a proof of complete memory zeroization.
- Panic reset uses two directory renames with rollback on exceptions. Cold-start `recover(directory)` restores the deterministic previous directory only when the destination is absent; normal password unlock subsequently authenticates it. If both generations exist, neither is deleted or automatically selected. The gap between renames is not crash-atomic, filesystem durability still requires device validation, and old encrypted blocks cannot be securely erased on flash by deleting a backup directory.
- Archive defaults are 1 GiB total/container, 512 MiB per entry, 10,000 entries. ZIP64, comments, directory entries, noncanonical names, WAL/SHM and unknown files are deliberately rejected. Ciphertext contains its normal format/header metadata; it is not literally an unstructured random disk image.
- Independent external cryptographic/protocol review and device threat gates remain mandatory.
