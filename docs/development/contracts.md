# Integration contracts

All paths use package `dev.mx3.nomessages`. Core sources below `core/src/main/kotlin/dev/mx3/nomessages/core`. Shared contracts are root-owned: `crypto/Crypto.kt`, `app/.../ui/UiContract.kt`. Do not redefine these.

## Crypto
`Crypto` delegates to libsodium: password Argon2id p=1; AEAD XChaCha20-Poly1305 as nonce24 || ciphertext || tag16; SHA256; keyed BLAKE2b32; Ed25519 pk32/sk64. `NativeCrypto` implements this interface using JNI library `nomessages`. It must work both host JVM and Android, no insecure fallback. Password input is UTF8 NFC handled by vault. Rust exported JNI names belong to `dev.mx3.nomessages.core.crypto.NativeCrypto` (methods can use private native suffix wrappers). Rust library module names and cargo manifest are owned by root; agents supply isolated .rs modules.

## Vault
Vault task owns `vault/*`, `files/*` plus tests. Publish exact public APIs to root early. Use a storage adapter interface for SQLCipher lifecycle; no Android imports in core. All code runs synchronously on app's serialized IO dispatcher. Real and decoy wraps always derive before selecting; passwords validated at setup with the in-repo `estimateStrength` (`PasswordStrength.kt`), no third-party estimator. Archives use streams, enforce total/entry/count limits and reject symlinks/traversal/duplicates. Never write plaintext. Streaming file format authenticates length and terminal chunk (including empty file). NativeCrypto available via Crypto interface.

## Protocol
Protocol task owns `protocol/*`, `groups/*`, `docs/development/pairing.proto` (schema movido de `docs/development/pairing.proto` (schema movido de `core/src/main/proto` em 2026-09-14, T4.5) em 2026-09-14, T4.5), and corresponding tests. Crypto interface above available. Use official libsignal Java classes and supply state serializer/transaction-friendly in-memory store. No UI or Android dependencies. QR signed Ed25519 identity binds libsignal bundle and onion; same transcript/SAS in both peers. Group graph verifies bilateral signed edges. Publish APIs and pinned libsignal dependency to root/build agent early. libsignal JNI is its own official upstream library, not `nomessages`.

## Native network and MLS
Native task owns `native/src/tor*.rs`, `native/src/mls*.rs` and `core/.../nativebridge/{TorNative,MlsNative}.kt`. Native crypto task owns crypto*.rs and Kotlin crypto/NativeCrypto.kt. Root assembles Cargo.toml/lib.rs. Tor daemon lives in Android :tor process; no plaintext secret keystore. Dedicated seed from vault gives stable onion. TorNative has start(seed,stateDir,bridgeLines), status/onion, send(onion,frame), poll(timeout), stop. Enforce onion-only destination, length budgets, per-peer isolation. Prefer poll result carries opaque complete framed bytes and connection reply support. Return native metadata/errors via explicit exceptions, no secret logs. MLS state is serialized opaque bytes returned to caller for SQLCipher storage after each mutation. Members use Ed25519 credentials; app transports welcome/commit via 1:1 ratchet. Supply typed Kotlin result classes or a documented strict binary wire codec and tests. No fake MLS or pairwise application-message fanout.

## UI
UI task owns all `app/.../ui/*` EXCEPT UiContract.kt, plus `app/src/main/res/*`. Root entry composable `NoMessagesApp(state: UiState, actions: UiActions)`. Real data only, no production demo fallback. UiState replacement with `unlocked=false` must erase remembered chat/secret contents by disposing the unlocked subtree. Setup/lock take CharArray and immediately clear UI password fields on submit. Long operations use state.busy. Barcode scanning composable owns CameraX permission and yields a scanned string through actions.readPairing; QR generation ZXing. Resources PT-BR default/EN, own icon, no official Meta assets. Attachment viewer inside app only, receives in-memory bytes, never external intent, cache or MediaStore. UI may handle permissions using ActivityResult but cannot persist content. Root owns Activity and OS lifecycle wiring.

## App runtime
Root owns storage/runtime/application/activity. SQLCipher + transactions cover contacts, Signal sessions, messages, outbox, MLS states and pairing evidence. Handles generation tokens for cancel/lock; no job may resurrect a closed session. File/photo/audio import processes streams into AEAD; no MediaStore. Service notification title NoMessages, empty body. Export/import operates on ciphertext with DB closed/checkpointed. Pairing progress and errors must never claim success before both SAS confirmations.
