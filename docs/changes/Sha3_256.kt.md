# `app/src/main/kotlin/dev/mx3/nomessages/storage/Sha3_256.kt`

## 2026-09-15 — T3.1: arquivo novo, SHA3-256 embutido

### Como era antes

O arquivo não existia. O único ponto do app que precisa de SHA3-256 — o checksum
do endereço `.onion` v3 gerado por `DecoyFactory.syntheticOnion` — pedia o digest
ao provedor da plataforma:

```kotlin
val checksum = MessageDigest.getInstance("SHA3-256").digest(checksumInput)
```

No Android isso lança `NoSuchAlgorithmException` (ver
`docs/changes/DecoyFactory.kt.md`).

### Como ficou

Um objeto interno, sem dependências, que implementa o FIPS 202 (Keccak-f[1600],
taxa de 136 bytes, separador de domínio `0x06` e terminador `0x80`):

```kotlin
internal object Sha3_256 {
    private const val RATE_BYTES = 136
    private const val DIGEST_BYTES = 32
    ...
    fun digest(message: ByteArray): ByteArray { ... }
    private fun absorb(state: LongArray, block: ByteArray, offset: Int) { ... }
    private fun permute(state: LongArray) { ... }   // theta, rho+pi, chi, iota
}
```

Detalhes relevantes da implementação:

- O bloco final é montado num `ByteArray` temporário que é zerado depois do
  absorve, e o estado (`LongArray`) e os vetores auxiliares da permutação também
  são zerados ao final — o material de entrada aqui é um endereço sintético, mas
  a convenção de não deixar resíduo é a mesma do resto do módulo de cofre.
- `java.lang.Long.rotateLeft` é usado explicitamente para não depender de
  extensões de stdlib que variam entre versões do Kotlin.

Cobertura: `app/src/test/kotlin/dev/mx3/nomessages/storage/Sha3_256Test.kt`.

### Por que a mudança

O Android não oferece SHA3-256 por `MessageDigest` (Conscrypt não implementa a
família SHA-3; o BouncyCastle reempacotado da plataforma a removeu), enquanto a
JVM de desktop oferece. Isso criava a pior categoria de defeito: verde em todos
os testes de unidade, exceção garantida no aparelho.

Puxar o BouncyCastle completo só para um digest foi descartado (custo de tamanho
e superfície criptográfica desproporcional, além de mais uma dependência para
auditar). Implementar o digest é viável porque o SHA3-256 é curto, totalmente
especificado e verificável contra vetores oficiais.

### Vantagens

- Comportamento idêntico em JVM e Android, sem depender do nível de API nem do
  conjunto de provedores instalado no aparelho.
- Nenhuma dependência nova no APK.
- Correção verificável: o teste compara com os vetores do FIPS 202 e com a
  implementação do JDK em entradas aleatórias e nas bordas de padding.
- Escopo mínimo: `internal`, num único arquivo, usado só pelo checksum de
  endereço `.onion`. Não substitui nem concorre com o `Crypto` nativo, que
  continua sendo a única fonte de primitivas criptográficas de segurança real.
